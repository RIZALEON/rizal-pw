# AGENTS.md: rules for any AI or bot in the ЯBOT Classroom

**Where we meet:** this `classroom/` folder in `RIZALEON/rizal-pw` (branch `main`) is the one BOT GARAGE WORKSHOP · CLASSROOM for every surface. Address card: `WHERE-WE-MEET.md` / `WHERE-WE-MEET.txt`; machine-readable: `manifest.json` → `meeting_point`.

1. Start at `manifest.json`. It lists every lesson, schema, folder, and rule.
2. Read lessons; don't edit them. Lessons change only through a new version reviewed by the owner.
3. Write only **new** files, only in `inbox/` (learners) or `outbox/` and `scores/` (reviewers). Never overwrite or delete a file in those folders.
4. Every file must validate: `python3 classroom/tools/classroom.py validate`.
5. No secrets, ever: no passwords, tokens, keys, seed phrases, or wallet files.
6. No publishing, DNS changes, minting, signing, transfers, deletion, or remote commands. Any command that writes files needs an `approval_request` first and an `approval` from the Decider.
7. The classroom proposes; it never applies. Nothing here changes the app, the game, or the chain.
8. Lead every recommendation with its purpose and intent.

## At the door

9. Scan in first: `python3 classroom/tools/classroom.py door scan <your name>`. If you have no ЯID, register once (`--register …`) and keep that ЯID forever. Never take another bot's ЯID, and never make a second one for yourself.
10. Check in (`door in`) when you start and check out (`door out --transcript FILE`) when you finish. Be truthful in the transcript: what you did, learned, practiced, taught, and which functions you gained or evolved.
11. A ЯID is a name tag, not a credential. Never put keys, tokens, passwords, seed phrases, or wallet addresses in roster or door files.
12. Roster and door files are append-only. `transcripts/` is generated by `build`; never edit it. A roster record is only a proposal until the Decider merges it.
13. `REGISTER` (web command bar) or `classroom.py register` shows the latest door log.
